# LaunchDock 项目技能

## 使用原则

- 只服务当前 LaunchDock 项目，不迁移为全局通用技能。
- 默认使用中文编写文档、说明、注释、界面文案和错误提示。
- 后续新增文件和目录使用简洁、合适的英文名称；文件内容仍默认使用中文。
- 仓库内路径使用相对路径，不写死任何开发者本机绝对路径。
- 用户要求实现功能时，先读取根目录 `AGENTS.md`，再根据当前代码结构做最小必要修改。
- 每次生成或修改代码时，同步更新根目录 `development-log.md`，并记录日期、时间、修改范围、涉及文件、具体内容和验证情况。
- 版本号（例如 `0.2.0`）仅在正式完成一轮开发、重新打包或上线更新时才记录到开发日志，日常开发和测试不改变版本号。
- 每次新增、修改、删除或移动 Skill 时，同步更新根目录 `AGENTS.md` 中的项目专属 Skill 说明。
- 始终优先保护用户本地数据，避免无确认删除或覆盖。

## 产品目标

LaunchDock 是一个本地“启动坞 / 启动屋”，用于管理多个学习或工作项目。每个项目保存一组常用网页链接，用户选择项目后可以一键打开该项目的默认启动链接。

典型场景：

- 用户每天学习 PyTorch，需要打开视频课程、Notion 笔记、官方文档和练习仓库。
- 用户创建“PyTorch 学习”项目，并在创建时添加这些链接。
- 用户之后只需点击该项目的“启动”，即可进入学习状态。

## 工作流要求

### 创建项目

创建项目时应允许用户选择是否立即配置初始链接。用户可以先只创建一个空项目，之后再补充链接和说明。

项目创建流程应覆盖：

1. 输入项目名称。
2. 选择或确认项目保存位置。
3. 选择是否立即添加链接。
4. 如果添加链接，则填写一个或多个链接并设置是否默认启动。
5. 如果暂不添加链接，则创建空项目。
6. 保存到启动坞对应项目文件夹。

### 删除项目

删除项目属于高风险操作。

实现或设计时必须考虑：

- 删除前确认。
- 明确展示将删除的项目名称。
- 重命名项目时，同步重命名启动坞 `projects/` 下的本地项目文件夹，并更新 `project.json` 里的 `folder_name`；如目标文件夹名已存在，自动生成不冲突的文件夹名，不能覆盖其他项目。
- 支持启动项目管理模式下勾选多个启动项目并批量删除。
- 启动项目管理模式应提供全选、取消全选和反选功能。
- 如后续支持回收站或备份，优先移动到备份区，而不是直接永久删除。
- 未经用户确认，不删除项目文件夹。

### 管理链接

链接管理应支持：

- 新增链接。
- 编辑链接名称。
- 编辑 URL。
- 设置是否默认启动。
- 删除链接。
- 调整链接顺序。
- 支持单个项目内的启动项管理模式。
- 启动项管理模式下可勾选该项目内多个启动项，并批量删除。
- 启动项管理模式应提供全选启动项、取消全选和反选功能。

链接或本地文件启动项至少包含：

```json
{
  "id": "uuid",
  "name": "官方文档",
  "url": "https://example.com 或 C:/path/to/file.pdf",
  "default_open": true,
  "order": 1
}
```

### 一键启动

启动项目时：

- 只打开 `default_open` 为 `true` 的链接。
- 按 `order` 顺序打开。
- 网页链接使用系统默认浏览器。
- 本地文件或文件夹使用系统默认程序打开。
- 如果没有可启动目标，用中文提示用户。
- 如果某个目标为空、URL 明显非法或本地路径不存在，提示用户修正，不静默失败。

## 启动坞约定

用户数据应保存在一个用户自定义的“启动坞”大文件夹中。

推荐结构：

```text
用户选择的启动坞文件夹/
  launchdock.json
  projects/
    项目文件夹名/
      project.json
```

要求：

- 用户可以自定义启动坞根目录。
- 用户首次下载并启动软件时，不应自动创建默认启动坞路径；初始状态应为空。
- 没有创建或选择启动坞前，用户不能创建启动项目。
- 没有启动坞时，主界面应提示用户先创建启动坞，并说明启动坞用于保存启动项目的存储位置。
- 程序需要记住启动坞路径。
- 所有小项目都保存在启动坞根目录下的 `projects/` 中。
- 每个小项目一个独立文件夹。
- 每个小项目的数据保存在自己的 `project.json` 中。
- 全局配置保存在启动坞根目录的 `launchdock.json` 中。
- 路径必须兼容 Windows，支持中文、空格和特殊字符。
- 文档、配置和示例不得依赖维护者本机路径，仓库内说明统一使用相对路径。

项目文件夹命名：

- 可以基于项目名称生成。
- 必须处理重名。
- 必须避免非法路径字符。
- 不要依赖文件夹名作为唯一标识，唯一标识使用 `uuid`。

## 界面风格

窗口使用 PySide6 + QFluentWidgets 实现，参考 `ok-oldking/ok-wuthering-waves` 的视觉风格和 `ok-oldking/ok-script` 的 Qt/Fluent 桌面应用架构。

可借鉴：

- 工具型桌面应用气质。
- 主操作突出，例如“一键启动”。
- 深色主题，类似 Windows 11 Settings / WinUI 3 风格。
- 左侧垂直导航，包含图标和文字。
- 右侧主区域使用设置页面布局。
- 项目和启动项使用横向圆角卡片。
- 卡片左侧放图标、标题和说明文字。
- 卡片右侧放开关、编辑图标、下拉箭头或主要操作按钮。
- 主界面右上角提供“新建”按钮。
- 启动项目以卡片式整齐排列在主界面。
- 项目卡片右上角提供编辑图标，用于编辑项目并显示启动内容。
- 项目卡片右上角不提供重复的添加按钮，添加启动项入口保留在项目卡片底部。
- 项目卡片提供折叠按钮，点击展示全部启动项，再次点击收起启动项。
- 每条启动项右侧提供开关按钮控制是否启动，并提供编辑图标编辑名称和地址。
- 启动项列表默认只显示启动项名称，不直接展示完整 URL 或本地路径，避免长地址撑开卡片并影响“启动”按钮可见性；完整地址在编辑对话框中查看和修改。
- 每条启动项不显示上移、下移箭头，除非后续设计明确可用的排序交互。
- 每个项目卡片下方提供启动按钮，启动所有已启用的网页链接或本地文件目标。
- 顶部提供“管理项目”模式，进入后可勾选启动项目，并支持全选、取消全选、反选和批量删除。
- 每个项目卡片提供“管理启动项”模式，进入后可勾选该项目内启动项，并支持全选、取消全选、反选和批量删除。
- 项目卡片区域背景保持透明或与主区域一致，避免出现突兀的大块黑色矩形背景。
- 适合高频重复使用的紧凑界面。
- 现代、稳定、直接的视觉感受。
- 青色作为强调色，背景保持低对比度，不要太花。
- 字体接近 Segoe UI。
- 多语言界面中，语言下拉列表里的各语言名称使用对应语言自身的写法，例如 `English`、`日本語`、`한국어`、`Español`；只有“使用系统设置”这一项跟随当前界面语言变化。

避免：

- 照搬参考项目的游戏业务内容。
- 使用参考项目的图标、品牌素材或游戏元素。
- 做成营销落地页。
- 加入过度装饰和影响效率的动画。

## 技术偏好

- 优先 Python。
- UI 层使用 PySide6 + QFluentWidgets。
- 不再使用 Tkinter 实现主界面。
- `launchdock/app.py` 负责 UI 层。
- `launchdock/models.py` 和 `launchdock/storage.py` 是业务核心，迁移或调整 UI 时尽量保持不变。
- 打开网页使用 `webbrowser`。
- JSON 使用标准 JSON API 读写。
- 注释和用户可见文本使用中文。
- 代码应适合初学者阅读，避免过度抽象。

## 应用图标

- 软件图标源文件为 `assets/icon.png`。
- 应用运行时应使用该文件作为窗口图标。
- 图标源推荐使用带透明通道的 PNG；如果源图缺少透明通道，运行时可以基于角落背景色临时剔除纯色背景，但不应覆盖或修改原始图标源文件。
- 应用窗口标题栏显示 `LaunchDock`，不追加中文后缀。
- 后续打包为桌面软件时，也应使用该文件作为软件图标源。
- 如果打包工具要求 `.ico` 等格式，应从 `assets/icon.png` 派生生成，不要替换原始图标源。

## 修改文件时的检查清单

处理本项目需求或代码时，至少检查：

- 是否遵守中文默认语言。
- 是否使用英文文件名和中文文件内容。
- 是否避免写死开发者本机绝对路径。
- 是否保护用户数据。
- 是否尊重用户自定义启动坞路径。
- 是否把小项目保存在启动坞根目录下的独立项目文件夹。
- 是否允许创建空项目并后续补充链接。
- 是否把创建/删除项目作为高频重复流程来设计。
- 是否支持管理项目模式下全选、取消全选、反选和批量删除项目。
- 是否支持单个项目内管理启动项、全选启动项、取消全选、反选和批量删除启动项。
- 是否支持启动项折叠和展开。
- 是否保持“一键启动”作为核心体验。
- 是否保持 WinUI 风格：深色、左侧导航、右侧卡片、青色强调、桌面软件观感。
- 如果涉及多语言设置，语言列表是否保留各语言原生名称，并只让“使用系统设置”跟随当前界面语言变化。
- 如果涉及窗口、入口或打包配置，是否继续使用 `assets/icon.png` 作为软件图标源。
- 如果涉及窗口标题，是否保持显示为 `LaunchDock`。
- 是否在生成或修改代码后更新 `development-log.md`，并写清日期与具体时间。
- 日常开发不应变更版本号，版本号仅在正式打包或上线发布时才更新。
- 如果涉及 Skill 变更，是否同步更新 `AGENTS.md`。
